# DeepSeek 官方接口的安全接入

当前客户端默认使用 **Uni AI 网关（qiniu）**。网关里的 DeepSeek Flash / Pro 模型继续可用，客户端通过 `uni-ai-x-co.getTmpToken` 获取临时凭据，不保存服务商的长期 API Key。

`config.uts` 中被注释的 `deepseek` 配置，以及 SDK 中的官方接口适配代码，仅供理解接口格式和多轮工具调用使用。示例 Key 已替换为 `********`，官方直连配置、自动安装和服务商注册均已注释，界面也不会再引导切换到官方直连。不要取消注释后将真实 Key 填入前端。

## 正确的调用路径

```text
App / Web 客户端
    │ 用户登录凭证 + 业务请求
    ▼
uniCloud 云函数 / 云对象，或自有 HTTPS 后端
    │ 服务端读取长期 Key，调用 DeepSeek
    ▼
DeepSeek 官方接口
```

将 Key 保存在 uniCloud 服务端配置（如未纳入版本控制的 uni-config-center 私有配置）或后端环境变量／密钥管理服务中。不要把真实 Key 放入前端配置、安装包、网页、客户端环境变量、本地存储、可下载的配置文件或代码仓库。

中转服务需要完成用户身份、功能权限、额度与请求参数校验，再选择允许的模型和接口。它可以代理聊天的 SSE 流、文件上传、搜索／网页读取、OCR、ASR、TTS 等实际需要的官方能力，并将必要结果返回客户端；不要将长期 Key 返回客户端，也不要开放可任意指定上游地址和鉴权头的通用转发接口。客户端停止回答时，中转也应中断对应的上游请求；流式结束、错误和超时需要明确传回客户端。

现有 Uni AI 网关的临时 Token 方案可以继续沿用。DeepSeek 官方 Key 不应被包装成“临时 Token”直接下发；官方接口接入应由自己的云端持有 Key 并代理请求。

本次只关闭官方前端直连并提供接入说明，没有部署新的中转服务。后续接入时，应先实现服务端接口，再为它配置独立服务商和相应能力，不能靠重新启用直连示例完成上线。

## 已经使用过的 Key

删除工作区中的 Key 不会删除已有 Git 提交、旧安装包或已分发文件中的副本。曾进入这些载体的 Key 应在服务商控制台作废并重新生成，新 Key 仅保存到服务端。清理 Git 历史属于独立操作，需与仓库协作者协调后处理；本次未改写已有提交。
