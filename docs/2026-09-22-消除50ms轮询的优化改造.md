# 消除 50ms 轮询的优化改造

修改日期：2026-09-22

## 一、背景与目标

主线程消费 Worker 数据（ops 批次与 state 对象）原为 50ms 轮询：runner 与 demo runner 用 `setInterval(..., 50)` 定时读取 runtime 暂存的 `pendingLibmarkOps` / `latestLibmarkState`。

此前的两项优化（SSE 收流 100ms 节流、一次 feed 的 ops 合并为单条消息）改变了频率结构：

- 消息产生：ops 批次约 10 次/秒 + state 约 3.3 次/秒，合计约 13 次/秒
- 消费轮询：20 次/秒

轮询原本承担的"合并高频事件、限制 SDK 重算频率"职责已由上游节流与批量投递接管，轮询退化为高频空读，并给端到端增加最多 50ms 的额外延迟。本次改造将消费机制改为**数据到达即消费（事件驱动）**，仅保留微信小程序的轮询（其无 Worker 消息机制）。

## 二、改造方案

### 2.1 数据到达通知

- runtime（`uni-ai-worker-runtime`）提供 `setAiWorkerDataListener(listener)`，在消息存入暂存区后通知；触发点覆盖 ops 批次、state、init-error、snapshot、onError 两类分支
- runner（`uni-ai-x/sdk/requestAiRunner.uts`）与 demo runner 在启动时注册消费回调、停止时注销
- 微信小程序分支保持原有 50ms 轮询

### 2.2 回调存活的必要条件：@UTSJS.keepAlive

该方案要求 JS 侧闭包被 Kotlin 插件保存后反复调用，这里存在跨语言边界，需要满足两个条件才能稳定工作。

**编译边界**（vapor 模式按 `dcloudext.type` 决定编译目标）：

| 模块 | `dcloudext.type` | Android 编译产物 |
| --- | --- | --- |
| `uni-ai-x`（runner / SDK 所在） | `unicloud-template-page` | **JS**（`app-service.js`） |
| `demo/markdown/*`（项目源码） | — | **JS**（`app-service.js`） |
| `uni-ai-worker-runtime` | `uts` | **Kotlin**（`index.kt`） |
| `uni-ai-worker` / `libmark` / `uni-cmark` | `uts` | Kotlin |

即：只有 `dcloudext.type = "uts"` 的插件编译为原生 Kotlin，其余（模板插件、项目源码）随项目编译为 JS。因此运行时是"JS 侧闭包 → Kotlin 插件保存"的跨语言传递，Kotlin 侧持有的实际是 JS 函数的代理对象（`UniUTSMethodRegister$Companion$0`）。

**必要条件**：

1. HBuilderX 4.25 起，插件导出方法中的回调参数为防内存泄漏**默认触发一次后自动回收**；需要多次触发时必须使用 HBuilderX 4.27+ 的 `@UTSJS.keepAlive` 注解声明回调持续存活；
2. 该注解**不支持 `export const xxx: Type = function` 导出形式**，必须使用 `export function`。

```uts
@UTSJS.keepAlive
export function setAiWorkerDataListener(listener: AiWorkerDataListener | null): void {
    // #ifndef MP-WEIXIN
    dataListener = listener
    // #endif
}
```

注解生效后，编译产物会为 JS 回调建立 `UTSCallback.fnJS` 转发闭包缓存（无注解版本没有这段逻辑）：

```kotlin
return setAiWorkerDataListener(if (params[0] == null) null else
    (((params[0] as UTSCallback).fnJS ?: (fun(): Unit {
        (params[0] as UTSCallback)()
    }).also(fun(fnJS): Unit {
        (params[0] as UTSCallback).fnJS = fnJS
    }))...
```

**维护约束**：

- `setAiWorkerDataListener` 必须保持 `export function` + `@UTSJS.keepAlive`，不可退回 `export const` 形式；
- Android / iOS 平台同时配置（当前写在共用代码中，一次生效）；
- 回调将常驻内存，注册频率保持每请求一次，避免反复注册造成泄漏。

## 四、验证结果

- Android 真机（自定义基座）：事件驱动下完整 Markdown 场景持续流式渲染——BLOCK 事件 116 条、块序号增长至 #26、状态行字符数持续增长，表格、块引用、代码块正常显示
- 编译验证：`launch app-android --compile true` 与 `launch app-harmony --compile true` 均通过
- iOS / Web 未做真机验证（同一机制与注解，后续按需回归）
