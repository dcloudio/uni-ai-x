# 会话记录持久化与重建方案优化

修改日期：2026-09-23

## 一、背景与问题

鸿蒙真机实测：会话流式过程中块公式渲染正常，但杀掉应用重启后，历史消息显示为 Markdown 源码（公式显示 LaTeX 原文）。

## 二、根因分析

1. 鸿蒙/Android 的 libmark 链路中，重启渲染所依赖的 `markdownAst` 仅在 `onState('completed')` 且 `isActiveAiMsg()` 通过时保存：
   - 用户点“停止”：`abortRequest()` 先执行 `answerGeneration += 1`，随后的 `onState('stop')` 回调被 `isActiveAiMsg()` 拦截，不做任何保存；
   - 直接杀掉应用：`updateMsg2Storage` 为纯防抖（每次调用重置 1 秒定时器），流式期间永不落盘，存储中只剩旧快照；
   - demo 模式的非 full 场景（如“公式”）为无限流，永远不会进入 completed 分支，问题必现。
2. 重启后 `markdownAst`/`markdownHtml` 均为空，`getMarkdownBlocks` 返回空 blocks，`renderItemList` 回退到 `msg.body` 纯文本渲染，导致整条消息（公式及其他 Markdown）显示源码。
3. 存储层面：鸿蒙 `uni.setStorageSync` 为 preferences `putSync + flush()`，每次写入都会整文件刷盘；若继续持久化含 SVG payload 的大 AST，长会话下写放大明显。

## 三、修复方案

### 3.1 总体思路

持久化只保留轻量原文（`body`），渲染数据不落 storage；重启后由原文用 libmark 重新解析（重建）生成 blocks；同时修复“停止/中断后状态不落盘”的问题。

数据流变化：

- 修复前：流式 ops → streamEntries（内存）→ blocks；completed 时序列化完整 AST（含 SVG）写入 storage
- 修复后：流式 ops → streamEntries（内存）→ blocks；storage 只存 body（2 秒节流）；重启后 body 重建 → streamEntries（内存 LRU）→ blocks

### 3.2 具体改动

1. 持久化与停止路径（`sdk/index.uts`）
   - `updateMsg2Storage` 由纯防抖改为固定 2 秒节奏节流（窗口内不重置定时器）+ 尾保；
   - 新增 `flushMsg2Storage()`：完成/停止/中断时立即落盘最终状态；
   - `onState('completed')`：不再生成/保存 `markdownAst`，改为 `libmarkStreamMarkComplete`（仅刷新完成态）+ `flushMsg2Storage`；
   - `onState('stop')` / `onRendered`：`rendered = true` 后立即 flush；
   - 记录 `streamingAiMsg`；`abortRequest` 在递增 generation 之前，对当前流式消息置 `rendered = true` 并落盘。
2. 重建与内存缓存治理（`sdk/libmark-stream-store.uts`）
   - 新增 `libmarkStreamRebuildFromText(msgId, text)`：主线程同步调用 libmark（createSession → feedChunk → finishSession → destroySession），ops 经 adapter 转换生成 blocks（真机实测单条 10~20ms）；
   - 新增 `libmarkStreamMarkComplete(msgId)`：仅刷新完成态，不序列化；
   - 新增 LRU：条目记录最近访问顺序，超过上限（默认 200 条）淘汰最久未访问；现有显式释放点保留。
3. 重建接入与单帧预算队列（`components/uni-ai-chat.uvue`）
   - `getMarkdownBlocks`：内存未命中且 body 非空时，预算内同步重建，超出则入队并先返回空（占位显示 body）；
   - 新增响应式 `rebuildVersion` 并纳入缓存失效比对；`renderItemList` 每次执行重置单帧预算（默认 3 条）；
   - 后台每 16ms 批处理 3 条，完成后 bump `rebuildVersion` 触发重算，自驱至队列清空；
   - 旧的 `markdownAst` 恢复路径保留，兼容迁移前数据。
4. 数据迁移（`sdk/storage-manager.uts`）
   - 新增 `uni-ai-storage-version`（当前 2）；
   - 打开会话时若版本低于当前，清空该会话消息的 `markdownAst`/`markdownHtml`（内存立即生效），后台分批重写 storage，全部完成后写入版本号（幂等）。
5. 平台范围
   - 仅覆盖鸿蒙/Android 的 libmark 链路；iOS/Web/微信小程序保持原有 cmark 持久化逻辑不变。

### 3.3 关键参数

| 参数 | 取值 |
| --- | --- |
| body 持久化节流间隔 | 2 秒 |
| 单帧重建预算 | 3 条 |
| 重建队列批处理 | 3 条 / 16ms |
| streamEntries LRU 上限 | 200 条 |

## 四、执行记录

### 4.1 改动文件

| 文件 | 内容 |
| --- | --- |
| `uni_modules/uni-ai-x/sdk/index.uts` | 节流持久化、flush、停止/完成路径、streamingAiMsg |
| `uni_modules/uni-ai-x/sdk/libmark-stream-store.uts` | 重建函数、MarkComplete、LRU、平台分叉 import |
| `uni_modules/uni-ai-x/sdk/storage-manager.uts` | 数据版本号、历史消息旧渲染字段的惰性清理与后台重写 |
| `uni_modules/uni-ai-x/components/uni-ai-chat.uvue` | 重建接入、单帧预算队列、缓存版本、重建后滚底刷新 |

### 4.2 实现要点

1. `updateMsg2Storage` 改为固定 2 秒节奏节流（窗口内不重置定时器），新增 `flushMsg2Storage()` 供终态立即落盘；`resetMsg` 改为 flush。
2. `onState('completed')` 不再序列化 AST，改为 `libmarkStreamMarkComplete`（仅刷新完成态）；`onState('stop')`/`onRendered` 立即 flush；`abortRequest` 在递增 generation 前对 `streamingAiMsg` 置 `rendered=true` 并 flush。
3. `libmarkStreamRebuildFromText` 在主线程完成 body → blocks 重建（实测单条 10~20ms，首轮 33ms）；`existing.textBlocks` 非空时直接复用，避免重复解析。
4. 重建后的列表内容高度突变会导致首帧原生视图未重绘（重启后界面空白、需滑动才显示），补充 `scheduleRebuildScroll()`：重建完成后若视图处于底部且用户未触摸，主动触发一次滚底刷新。
5. 迁移采用会话级惰性策略：`getChatMessages` 读取时清空内存中的旧字段，后台按 200ms 间隔逐条重写 storage，队列清空后写入 `uni-ai-storage-version=2`；仅鸿蒙/Android 生效。

### 4.3 关键参数（实际取值）

| 参数 | 取值 |
| --- | --- |
| body 持久化节流间隔 | 2000ms |
| 单帧重建预算 | 3 条 |
| 重建队列批处理 | 3 条 / 16ms |
| streamEntries LRU 上限 | 200 条 |
| 旧消息重写间隔 | 200ms/条 |

## 五、验证结果

真机（HUAWEI Mate 60 Pro，HarmonyOS）验证，`launch app-harmony --compile true` 编译通过。

| 场景 | 结果 |
| --- | --- |
| 旧数据（存量为空 AST、无源码回退）重启 | 公式由 body 重建，正常渲染为图片，不再显示源码 |
| "完整 Markdown"流式中直接杀应用 → 重启 | 内容完整（丢失窗口 ≤2s），无空白，自动停在底部 |
| "公式"无限流中点击停止 → 杀应用 → 重启 | `rendered=true`、body 落盘，公式正常渲染 |
| 流式自然完成 → 杀应用 → 重启 | `onState('completed')` 即时落盘，重启渲染正常 |
| 存储检查 | AI 消息 `markdownAst` 均为 0；8 条消息的 preferences 文件 19.5KB；旧消息 AST 字段被惰性清理 |
| 首帧空白回归 | 修复前重启偶发空白（需滑动才显示），补充重建滚底刷新后稳定显示 |
