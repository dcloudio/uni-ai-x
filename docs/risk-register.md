# 风险登记册

本登记册记录需要继续观察或验证的现象，不将尚未证实的原因当作缺陷结论。

## List-View 回收节点引用与实际行不一致

- **现象**：保存列表项节点引用后向下滚动，旧引用可能返回可见区域的坐标，但画面显示的是另一行。
- **当前证据**：安卓固定行高独立实验的三轮对照中，有一轮旧 `ROW 0` 引用与当前 `ROW 23` 是同一复用对象，而按 ID 已查不到 `ROW 0`；另两轮旧引用坐标在屏外。稳定后重新查询的可见行坐标与截图一致。设置滚动位置的同一时刻，实际位置也可能尚未提交。
- **风险**：如果跨回收或布局更新长期持有节点引用，可能把另一行的坐标用于滚动边界或可见性判断，导致错误决策。
- **状态与后续**：现有证据不足以认定坐标 API 本身有误；动态行高场景尚未覆盖。后续应按当前行身份重新查询，并在布局稳定后对照实际画面，必要时单独复现。当前不作为已确认的框架 Bug 上报。
- **本机实验材料**：`uni-agent-artifacts/recycled-coordinate-study/`（本地忽略目录，不随仓库提交）。

## Web List-View 滚动结束时的位置补偿

- **现象**：Web Vapor 列表滚动结束后可能出现额外的位置调整。
- **当前证据**：Alpha 5.38 源码中存在滚动期间累计行高变化偏移、停止约 150 毫秒后应用位置补偿的路径。独立实验页面因组件注册错误未能渲染，尚无有效动态对照。
- **风险**：若补偿时机或偏移量与动态行高、程序滚动相互影响，可能造成可见内容位移或卡顿；目前只是待验证的可能性。
- **状态与后续**：尚未证明补偿错误，也未证明它造成卡顿。需在可运行的 Vapor 环境中对照固定行高、滚动时上方或下方变高、停止后变高，分别记录滚动指令、实际位置与画面。当前不作为已确认的框架 Bug 上报。
- **本机实验材料**：`uni-agent-artifacts/web-scroll-offset-study/`（本地忽略目录，不随仓库提交）。
