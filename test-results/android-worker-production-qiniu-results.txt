Purpose:
Validate T01 through the production RequestAiRunner rather than an isolated
capability probe. The Android built-in-provider path must put the streaming AI
request, ArrayBuffer/SSE decoding, Markdown formula preprocessing and CMark in a
Worker, then let the main thread enrich and publish immutable token snapshots.

Scope decision:
- Only Android and qiniu are required by the current acceptance scope.
- Bailian was explicitly excluded and was not called.
- No cloud object, function, gateway or provider configuration was uploaded,
  deployed or modified.
- Temporary-token acquisition remains a one-time main-thread preflight. The
  token value is passed in memory and is never displayed, logged or persisted.
- Custom providers and non-Android platforms retain their previous request path.

Production boundary under test:
1. RequestAiRunner obtains the qiniu provider configuration and short-lived
   token on the main thread.
2. The Worker starts the actual chunked deepseek-v3 completion request.
3. Every received ArrayBuffer goes directly through the stateful UTF-8/SSE
   decoder in that Worker.
4. The Worker accumulates content/reasoning, preprocesses formulas and invokes
   synchronous Android CMark on each throttled snapshot and at terminal.
5. The runtime plugin stores only the latest immutable JSON snapshot. The main
   thread polls it every 50ms instead of receiving one typed callback per tag.
6. The main thread assigns stable token IDs/reuses nodes and performs rendering
   enrichment that currently depends on UI capabilities: table sizing, code
   highlighting, formula SVG and Mermaid SVG.

Automatic test sequence:
1. Request A asks for a long Markdown response.
2. After the first non-empty production onMsgBody callback, abort Request A.
3. Start Request B after 50ms with the same production RequestAiRunner path.
4. Require Request B to finish through the real [DONE] sentinel.
5. Require heading, list, block_quote, table and code_block tokens.
6. Require at least two math tokens, two rendered formula SVG href values and
   one highlighted JavaScript code block.
7. Require zero callbacks from Request A after cancellation.

Test procedure:
1. Confirm the Android target:
   adb devices -l
2. Clear the device log before the isolated run:
   adb -s 192.168.2.5:5555 logcat -c
3. Build and launch the production qiniu regression page:
   /Applications/HBuilderX-Dev.app/Contents/MacOS/cli launch app-android \
     --project /Users/json/Desktop/code/uni-ai-x \
     --deviceId 192.168.2.5:5555 \
     --playground custom \
     --native-log true \
     --cleanCache true \
     --pagePath pages/repro-worker-real-ai/index
4. Wait for the explicit gate-success result.
5. Capture the isolated application/CMark records:
   adb -s 192.168.2.5:5555 logcat -d -v threadtime \
     -s JSConsole:D console:I CmarkJNI:I AndroidRuntime:E
6. Scan the application process log for cancellation/runtime failures:
   adb -s 192.168.2.5:5555 logcat -d -v threadtime --pid=16395 \
     | rg -i "dead thread|IllegalStateException|TypeError|AndroidRuntime|worker error|FATAL EXCEPTION"
7. Retrieve the HBuilderX last-build record:
   /Applications/HBuilderX-Dev.app/Contents/MacOS/cli logcat app-android \
     --project /Users/json/Desktop/code/uni-ai-x \
     --deviceId 192.168.2.5:5555 \
     --mode lastBuild
8. Launch the normal chat entry with the local Markdown fixture and inspect its
   screenshot plus process-level fatal-error log.

Conclusion:
PASS: the production Android qiniu RequestAiRunner now runs the hot streaming
      request, ArrayBuffer/SSE decode, formula preprocessing and CMark in Worker.
PASS: latest-only immutable snapshots reach the main thread and complete the
      production table/code/formula enrichment path.
PASS: cancellation followed by immediate restart produced no stale application
      callback and no dead-thread/runtime warning.

Evidence boundary:
- T01 is complete for the agreed Android/qiniu scope. This report does not claim
  Bailian, iOS, Harmony or Web coverage.
- Temporary-token acquisition is still a main-thread cloud preflight. Moving
  that cloud call into Worker would require a separate capability gate and is
  not included in the present cloud-safe scope.
- T02 is not complete: stable IDs, RichText/Image-oriented render enrichment and
  component-tree updates still happen on the main thread.
