Purpose:
Validate the remaining platform-sensitive part of T02 before changing the
production renderer: a Worker can classify all current render block kinds,
merge consecutive RichText content, assign stable keys, serialize nested
RichText-like nodes including attrs.style, and publish immutable snapshots that
the main page can parse and verify.

Scope:
- Deterministic local fixture only. No qiniu, Bailian or other network request.
- No cloud object, function, gateway or provider configuration was changed.
- This is a feasibility gate, not the production T02 migration.

Retained test code:
- Automatic page:
  pages/repro-worker-render-descriptions/index.uvue

Fixture:
- Base Markdown contains one heading, two consecutive paragraphs, a quote,
  thematic break, table, JavaScript code block, Mermaid block and math block.
- Extended Markdown appends one final paragraph.
- The Worker parses both versions through the real Android CMark JNI entry.

Expected descriptions:
- Base top-level tokens: 9.
- Extended top-level tokens: 10.
- Base descriptions: 7.
- Extended descriptions: 8.
- Kinds:
  rich,quote,divider,table,code,mermaid,math
- Base keys:
  u0,u3,u4,u5,u6,u7,u8
- Extended keys:
  u0,u3,u4,u5,u6,u7,u8,u9
- The first three tokens must merge into one rich description with
  tokenStart=0, tokenCount=3 and tokenTypes=heading,paragraph,paragraph.
- Every base key/kind pair must remain unchanged in the extended description.
- A nested h1 node, text child and attrs.style containing line-height:26px must
  survive Worker-side JSON stringify/parse and page-side JSON parse.

Snapshot contract:
1. Worker posts snapshot v1 for the base document.
2. The UTS plugin stores the latest snapshot as immutable JSON.
3. The page polls every 20ms and must observe v1.
4. Worker posts terminal v2 for the extended document after 150ms.
5. The page parses the complete nested description JSON and runs independent
   assertions before showing gate-success.

Conclusion:
PASS: Android Worker can build and serialize the coarse render-description
      contract needed by T02.
PASS: seven current block kinds, RichText merging, stable keys, token ranges,
      nested nodes and attrs.style all survive the Worker-to-main JSON boundary.
PASS: latest-only immutable snapshot polling works without per-tag UI callbacks.

Evidence boundary and implementation decision:
- The nested nodes in this gate are representative transport fixtures, not the
  complete production markdown-rich-text converter. Their purpose is to prove
  framework transport and type feasibility before moving production code.
- Production currently still builds block groups, stable IDs and complete
  RichText nodes on the main thread; T02 is not complete yet.
- The production implementation can now move pure stable-ID assignment, block
  grouping and RichText-node construction into a Worker-shared module.
- Table minimum width depends on the visible viewport; code highlighting and
  MathJax/Mermaid SVG generation depend on main-thread/WebView capabilities.
  Those remain explicit main-thread enrichment inputs rather than being falsely
  claimed as Worker-ready.
- RichText and Image are the primary content carriers, but table/code scroll
  shells, controls, dividers and loading/failure states remain necessary native
  component structure.
