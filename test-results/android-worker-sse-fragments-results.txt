=======================================

Purpose:
Prove that the production SSE core preserves UTF-8 code points, CRLF lines,
SSE fields and events when arbitrary RequestTask chunks split those boundaries.

Retained test code:
- Core: uni_modules/uni-ai-worker/utssdk/sse.uts
- Worker fixture: workers/markdownWorkerTask.uts, runSSEFragmentScenario()
- Automatic page: pages/repro-worker-capability/index.uvue
- Worker bridge: uni_modules/uni-ai-worker-probe

Input fixture:
- 93 UTF-8 bytes.
- SSE comment line, two JSON data events with raw Chinese text, and [DONE].
- Expected events: {"content":"第一条"} and {"content":"第二条"}.
- Fixed fragment sizes: 4,8,3,17,3,10,3,18,11,15,1.
- The boundaries deliberately split CR from LF, the data field name, SSE blank
  lines, and Chinese three-byte UTF-8 code points.
- A second decoder receives "data: tail" without a final newline/blank line;
  finish() must emit "tail".
- A third decoder receives two data lines in one event; the expected value is
  "first\nsecond" according to SSE multi-line data semantics.

Assertions performed inside the Worker:
- All 93 bytes are consumed by exactly 11 pushes.
- Exactly two JSON events are emitted and both match byte-for-byte.
- [DONE] is emitted exactly once.
- pendingByteLength() and pendingTextLength() are both zero.
- finish() flushes the unterminated tail event.
- Multiple data lines are joined with one newline.

Failure-path observations during implementation:
- Directly importing ../uni_modules/uni-ai-x/sdk/sse.uts from the Worker did not
  resolve because Worker compilation only exposes declared UTS plugin entries.
- Importing an internal plugin file generated a module namespace but not the
  exported class. Exporting from utssdk/index.uts resolved it.
- Uint8Array.set(array, nonZeroOffset) was misresolved by the UTS/Kotlin compiler
  as indexed element assignment. Explicit byte-copy loops compile and run.
- These are application-level import/compiler workarounds; none block production.
