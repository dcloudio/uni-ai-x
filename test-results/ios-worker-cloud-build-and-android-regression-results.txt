Purpose:
Verify that the common UTS Worker sources compile with the cloud Swift 6.2
toolchain while retaining generated Kotlin compatibility and Android runtime
behavior.

Retained implementation and test code:
- workers/markdownWorkerTask.uts
- pages/repro-worker-capability/index.uvue
- uni_modules/uni-ai-worker
- uni_modules/uni-ai-worker-probe
- uni_modules/uni-ai-worker-runtime

Source-level compatibility changes:
- Convert the platform Int returned by SSE byte search with Number.from before
  adding a UTS number.
- Give both direct uni.request success callbacks the explicit
  RequestSuccess<any> type.
- Copy probe Uint8Array values into a newly allocated, non-null ArrayBuffer.
  This avoids Android's nullable Uint8Array.buffer declaration and iOS's
  non-optional Swift ArrayBuffer declaration.
- Avoid Array<NSNumber>.join in generated Swift for fixed probe metadata.
- Coalesce the optional iOS result of JSON.stringify before assigning String.

Local iOS toolchain boundary
----------------------------

The local standard-base compile regenerated Swift but could not compile native
plugins because local Xcode supplies Swift 5.9.2 while HBuilderX 5.24's
DCloudUniappRuntime was built with Swift 6.2.4. The first failing module was
uni-cmark. This environment mismatch is not counted as a source-code failure;
the cloud Xcode 26.3 build below is the source compatibility verdict.
